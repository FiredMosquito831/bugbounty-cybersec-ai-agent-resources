What this archive is

Bounty Atlas is the Phase 1 research foundation for an autonomous bug-bounty and vulnerability-discovery agent. It indexes the methodology, papers, tooling and real-world patterns an agent needs to reason about security testing — and it is published as a site so the research can be searched instead of grepped.

How it was built

The archive was assembled through three research expansions, using deep-research workflows rather than a single search pass. Findings were cross-checked against the original papers and repositories; anything that could not be verified was dropped or annotated in place. The site itself is generated from the archive by two scripts:

  • scripts/build_data.py parses the source TSV, paper index, repository manifest and context document into JSON.
  • scripts/build_site.py renders the pages, copies the papers and emits the library dataset, sitemap and robots file.

Counts and descriptions on every page come from those files. If a number changes here, it changed in the archive — no copy is hand-maintained.

Responsible use

This archive is for authorised security research, education and defensive engineering. Nothing in it grants permission to test a system. Always obtain written authorisation from the system owner, respect the scope and rules of engagement, and stop when a test could affect availability or third-party data.

The repository intentionally contains no exploit code or active attack tooling: it contains links, metadata, papers and methodology. Reference repositories are read-only; the archive does not vouch for their safety and they must be audited before use.

Contributing

Sources can be proposed by editing repertoire/_new_sources_full.tsv (five tab-separated columns: collection id, collection header, title, URL, description) and re-running the two build scripts. See CONTRIBUTING.md for the validation checks. Broken links and mis-categorised entries are welcome as issues.
